QR Code Types, Explained: WiFi, vCard, Payment, Location and More

By Aurang Zeb Loona — Loona Automation

People talk about "making a QR code" as if there were one thing to make. In fact a QR code is just a container — a pattern that stores a short piece of formatted text — and its type is the format of what is inside. The format is what tells the scanning phone what to do: open a page, join a network, save a contact, start a payment. Choosing the wrong type is why some printed codes disappoint. This guide walks through the main types, what each one stores, and how to pick the right one for the job.

The Main Types and What They Hold

  • Website / URL. The simplest and most common type: the code holds a web address, and scanning opens it. Menus, posters, product pages and social profiles all travel this way. (A social-profile "QR" is really this type — a link to the profile.)
  • WiFi. Holds the network name, password and security type in a standard format (WIFI:T:WPA;S:YourNetwork;P:YourPassword;;), so phones offer to join instantly. Nothing about it touches the internet; the details live in the pattern.
  • vCard (digital contact). Holds a structured contact card — name, phone numbers, email, organisation, job title, address, website — which the phone offers to save straight into its address book. The modern replacement for typing details off a business card.
  • Payment. Holds a payment instruction in the format of a payment system: a UPI payment address in India, a PayPal.Me link, a mobile-money number, or a cryptocurrency address. Scanning opens the payer's app with the recipient (and sometimes the amount) already filled in.
  • Location. Holds geographic coordinates in a geo: link. Scanning opens the maps app at that pin — the code printed on delivery leaflets, event invitations and "find us" boards.
  • WhatsApp, SMS, phone and email. Each holds a ready-made action: a chat link with the number (and optionally a pre-typed message), an SMS with recipient and text, a tel: number ready to dial, or a mailto: with subject and body drafted.
  • Calendar event. Holds an event block (title, start, end, place) that the phone offers to add to the calendar — popular on wedding and conference invitations.
  • Plain text. Holds exactly what it says — a code word, a serial number, a short instruction. The phone simply displays it.

One contrast worth knowing: a traditional one-dimensional barcode holds only a short ID number, and the real information lives in a database the number points to. A QR code holds the information itself, which is why it works with no database and no connection.

Static vs Dynamic: The Choice That Outlives Printing

A static code stores its content directly in the pattern. It can never be edited afterwards — but it also never expires, never needs an account, and works forever, because there is nothing between your print and the phone. A dynamic code stores a short redirect address owned by a service; the service forwards scanners to your real destination, which lets you change the destination later and count scans — at the price of depending on that service staying alive and, usually, a subscription. Rule of thumb: anything printed for the long term — signage, packaging, business cards, books — should be static. Dynamic codes earn their keep in short marketing campaigns where changing the destination or measuring scans matters more than permanence.

Error Correction: Built-In Damage Tolerance

Every QR code carries backup data, in one of four levels: L (about 7% of the code can be damaged and still read), M (15%), Q (25%) and H (30%). Higher correction survives dirt, scratches and the logo some businesses place in the centre — but it makes the pattern denser, so the code must be printed larger to stay scannable. For a clean indoor print, M is plenty. For outdoor signage, product labels, or any code with a logo in the middle, choose Q or H and print generously.

How to Choose, in One Pass

Ask three questions. What should happen when someone scans? — that picks the type from the list above. Will this content ever need to change? — if yes, and the print is short-lived, consider dynamic; if no, static, always. Where will it live? — a rough environment or a logo overlay means high error correction and a larger print. And whatever you choose: test the finished code with two different phones, from the actual printed material, before committing to a print run.

Common Mistakes

  • Linking to a page behind a login. The code works; the destination refuses the guest. Link to something publicly viewable.
  • Cramming a full vCard into a tiny print. Long content means a dense pattern. Below roughly 3 cm, busy codes fail on ordinary cameras — simplify the card or print bigger.
  • Inverting the colours. Most scanners expect a dark pattern on a light background. Light-on-dark artwork fails on many phones even when it looks stylish.
  • Using a URL type for WiFi. A code that opens a web page showing the password is not a WiFi code — guests still have to type. Use the WiFi type and the phone joins by itself.

Frequently Asked Questions

Do QR codes expire?

Static codes, no — the content is in the ink. Dynamic codes last only as long as the redirect service behind them keeps running (and the subscription stays paid).

How much information can one QR code hold?

At the largest size and lowest error correction, up to about 4,296 letters and numbers, or 2,953 bytes of general data. In practice, shorter is better: every extra character makes the pattern denser and harder to scan at small sizes.

Can I change where a printed code leads?

Only if it was created as a dynamic code — that redirect is precisely what dynamic means. A static code's destination is fixed at printing, which is its weakness and its strength.

Is it safe to scan strangers' QR codes?

A code can point to a malicious website, so let your phone show you the destination before opening it (most camera apps preview the link), and never approve a payment a code unexpectedly asks for. The code itself cannot run anything on your phone.
